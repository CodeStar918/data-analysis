# 部署与操作手册

> 企业内网自然语言报表生成平台（阶段 8 交付物）
> 适用读者：系统管理员、运维人员

---

## 一、系统架构与组件

| 组件 | 说明 | 默认端口 |
| --- | --- | --- |
| frontend | Vue 3 静态站点（Nginx 托管，代理 /api） | 80 |
| backend | FastAPI 应用（Uvicorn） | 8000 |
| worker | Celery 异步任务执行（统计/明细结果生成） | - |
| postgres | 元数据库（用户、数据源、元数据、任务、审批、审计） | 5432 |
| redis | Celery 消息队列 | 6379 |
| DuckDB | 文件型分析引擎 + 结果库（`backend/data/report.duckdb`） | - |
| Ollama | 本地大模型（意图解析） | 11434 |

数据流：用户上传 Excel → pandas 解析 → DuckDB 导入 → 自然语言解析（Ollama）→ 校验确认 → Celery 任务 → 结果表 → 预览/导出。

---

## 二、环境要求

- 内网服务器（建议 4C8G 以上），已安装 Docker 与 Docker Compose
- Ollama 服务可达（同机或内网其他主机），已拉取模型（推荐 `qwen2.5:7b` 及以上）
- 业务数据库（SQL Server / MySQL / PostgreSQL）**只读账号**
- 浏览器：Chrome / Edge（员工使用，无需安装插件）

## 三、部署步骤

### 3.1 获取代码

```bash
git clone https://github.com/CodeStar918/data-analysis.git
cd data-analysis
git checkout master   # 发布分支
```

### 3.2 准备 Ollama 模型

```bash
ollama pull qwen2.5:7b
# 验证
curl http://<ollama-host>:11434/api/tags
```

### 3.3 配置环境变量

编辑 `docker-compose.yml` 中 backend / worker 服务的 environment（或改用 env_file）：

| 变量 | 说明 | 生产建议 |
| --- | --- | --- |
| `DATABASE_URL` | 元数据库连接 | `postgresql+psycopg://report:****@postgres:5432/report_platform`，**修改默认密码** |
| `JWT_SECRET` | 登录令牌密钥 | **必改**，≥32 字节随机串 |
| `SECURITY_KEY` | 连接串加密密钥 | **必改**，与 JWT_SECRET 不同 |
| `REDIS_URL` | 任务队列 | `redis://redis:6379/0` |
| `CELERY_EAGER` | 必须为 `false` | 由 worker 执行任务 |
| `OLLAMA_BASE_URL` | 模型服务地址 | 如 `http://10.0.0.5:11434` |
| `OLLAMA_MODEL` | 模型名 | 按实际拉取调整 |
| `MAX_UPLOAD_MB` | 上传大小限制 | 按需，默认 20 |

### 3.4 启动

```bash
docker compose up -d --build
docker compose ps          # 五个服务应为 running/healthy
docker compose logs -f backend   # 首次启动会自动建表并初始化管理员
```

### 3.5 初始化与验证

1. 浏览器打开 `http://<服务器IP>/`，用初始管理员 `admin / admin123` 登录
2. **立即修改 admin 密码**（当前版本请直接在元数据库 `user` 表更新 `password_hash`，或联系开发重置接口）
3. 健康检查：`curl http://<服务器IP>:8000/health` → `{"status":"ok"}`
4. 端到端验证：上传一个小 Excel → 工作台提问 → 确认 → 生成统计表 → 导出

## 四、日常操作

### 4.1 员工使用流程（写进培训材料）

1. **登录** → 「数据源」上传 Excel（.xlsx，≤20MB）或由管理员接入数据库
2. 「工作台」选择数据表 → 输入一句话需求（页面有示例）→ 点「解析」
3. 核对解析结果与 SQL 预览 → 点「确认无误并生成统计表」
4. 「结果中心」预览、导出 Excel/CSV
5. 明细加列需求：生成明细结果表后，如需写回原表，点「申请写回」填写理由，**等待管理员审批**

### 4.2 管理员操作

- **接入业务数据库**：数据源页 → 填写名称与连接串（务必只读账号）→ 接入后自动拉取表结构
- **数据字典维护**：元数据页 → 修改表/字段业务名称、维度/度量、默认聚合（影响解析准确率，务必准确）
- **写回审批**：审批页查看待审批申请 → 通过（写回自动执行）/ 驳回
- **审计查询**：`GET /api/audit`（可按 `action` 过滤：login / login_failed / upload / parse / job_create / export / approval_decide 等）

### 4.3 日志与排查

| 现象 | 排查 |
| --- | --- |
| 解析报 502 | `docker compose logs backend` 中有 Ollama 连接错误；检查 OLLAMA_BASE_URL 与模型服务 |
| 解析校验失败 | 检查元数据页字段业务名称/角色是否维护准确；查看返回的 errors 提示 |
| 任务一直 pending | worker 未启动：`docker compose up -d worker`；确认 CELERY_EAGER=false |
| 任务失败 | 任务详情 error_msg；常见为业务库不可达或字段类型异常 |
| 上传失败 | 仅支持 .xlsx；检查 MAX_UPLOAD_MB；空 sheet 会被跳过 |

常用命令：

```bash
docker compose restart backend worker   # 重启服务
docker compose logs --tail=100 backend  # 最近日志
docker compose down                     # 停止（pg_data 卷保留数据）
```

### 4.4 数据备份

- 元数据库：`docker compose exec postgres pg_dump -U report report_platform > backup_$(date +%F).sql`
- DuckDB 结果库：备份 `backend/data/report.duckdb`（建议停写窗口内拷贝，或每日定时任务）
- 上传的原始 Excel 由业务部门自行留存（系统当前不归档原件）

- [ ] 审计日志完整覆盖登录/上传/解析/任务/导出/审批
- [ ] 性能抽检：最大业务表（预估行数）聚合任务可在可接受时间内完成

## 六、已知限制与后续计划

| 项 | 说明 |
| --- | --- |
| 仅支持 .xlsx | 旧 .xls 需另装 xlrd，暂未支持 |
| admin 密码修改 | 暂无自助修改入口，通过数据库更新（计划阶段 8 UAT 反馈后补充接口） |
| 业务库大数据量物化 | 结果经 pandas 中转，超大结果集建议后续改用 DuckDB 直连扩展 |
| 解析准确率 | 依赖元数据字典质量；上线后按周回顾审计中的失败解析持续优化 Prompt |
